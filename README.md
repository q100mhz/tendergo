# TenderGo

Агрегатор закупок с zakupki.gov.ru (44-ФЗ и 223-ФЗ) с рабочими пространствами для команд. Работает по адресу https://itb2bhost.ru/tendergo.

- Список закупок: название, окончание приёма заявок, начальная цена, заказчик, закон.
- Ключи фильтрации на уровне организации: ОКПД2, КТРУ (по префиксу), регион, заказчик (ИНН или название).
- Карточка закупки: сведения из извещения, коды позиций, ссылка в ЕИС.
- Командная работа: избранное, статус, ответственный, заметки — видны только своей организации.
- Организации и сотрудники: владелец или администратор приглашает сотрудника ссылкой, выписанной на его email. Без ссылки вступить нельзя: email при регистрации не подтверждается, поэтому одного совпадения адреса недостаточно. Кто зарегистрировался без приглашения, получает своё пространство.

## Как устроены данные

Реестр закупок **один на всех**: каждая закупка хранится один раз (уникальна по реестровому номеру) и обновляется при повторной загрузке. Ключи организации применяются при запросе, а отметки организации (избранное, статус, заметки) лежат в отдельной таблице `org_tender_states`.

Воркер раз в час просматривает `EIS_MAX_PAGES` страниц выдачи ЕИС «Подача заявок» (44-ФЗ + 223-ФЗ, сначала недавно обновлённые). В карточках выдачи дата обновления указана без времени, поэтому каждый раз просматривается всё окно целиком. Закупки, у которых карточка не изменилась (сравнивается отпечаток её полей), пропускаются. Для новых и изменившихся закупок воркер открывает страницу извещения, а для 223-ФЗ ещё и вкладку лотов. Оттуда берутся заказчик, ИНН, регион, точный срок подачи заявок и коды ОКПД2/КТРУ. Новые ключи работают сразу, без догрузки. Закупки, у которых приём заявок закончился больше `RETENTION_DAYS` дней назад и которые никто не отметил, удаляются.

Ключи комбинируются так: **(любой ОКПД2 или КТРУ) И (любой регион) И (любой заказчик)**. Пустая группа выборку не ограничивает.

Особенности разбора извещений:
- **Заказчик.** Если закупку размещает уполномоченный орган, заказчиком считается организация из блока «Требования заказчика», а не сам орган.
- **ИНН заказчика (44-ФЗ)** берётся из ИКЗ, знаки с 4-го по 13-й.
- **Регион** определяется по полю «Регион», затем по ИНН заказчика, затем по адресу.
- **Срок подачи заявок** хранится в UTC. По 223-ФЗ ЕИС указывает его по местному времени заказчика, и оно пересчитывается по часовому поясу региона.

## Стек

- **Backend:** Node.js 24, TypeScript, Fastify, Drizzle ORM, PostgreSQL, cheerio (разбор страниц ЕИС), croner (расписание).
- **Frontend:** React 19, Vite, TanStack Query, React Router.
- **Деплой:** Docker Compose (Postgres, API, воркер, Caddy со статикой) за nginx сервера, который отдаёт HTTPS и проксирует путь `/tendergo`.

```
backend/   API, воркер загрузки, миграции (drizzle/), тесты (test/)
frontend/  SPA
deploy/    Caddyfile контейнера и блок для nginx сервера
```

## Локальная разработка

Нужен Node.js 24+. Postgres не обязателен: без `DATABASE_URL` используется встроенный PGlite в `backend/.data/`.

```bash
npm install
TENDER_SOURCE=mock npm run dev:api   # API на :3000, тестовые закупки (или eis, если ЕИС доступен из вашей сети)
npm run dev:web                      # сайт на http://localhost:5173/tendergo/
```

Проверки:

```bash
npm test            # тесты парсера ЕИС, загрузки и API на встроенном PGlite
TEST_DATABASE_URL=postgres://user:pass@localhost:5432/postgres npm test   # то же на настоящем PostgreSQL
npm run typecheck
npm run build
```

Тесты парсера используют настоящие страницы zakupki.gov.ru, сохранённые веб-архивом в 2025–2026 годах (`backend/test/fixtures/eis/`). Из них удалены скрипты и контакты сотрудников заказчиков. В CI тесты прогоняются и на PGlite, и на PostgreSQL 17.

Разовый запуск загрузки: `npm run ingest -w backend`.

После изменения `backend/src/db/schema.ts` создайте миграцию: `npm run db:generate -w backend`. Миграции применяются автоматически при старте API.

## Деплой

Пошаговая инструкция — в [DEPLOY.md](DEPLOY.md): загрузка на GitHub, подготовка VPS, первый запуск, автодеплой через GitHub Actions, бэкапы.

Коротко: сайт живёт по пути `BASE_PATH=/tendergo` на домене, который уже обслуживает nginx с другим сайтом. Сервер должен быть с российским IP: zakupki.gov.ru не отвечает зарубежным адресам. На сервере нужны Docker, клон репозитория и `.env` по образцу `.env.example`. Команда `docker compose up -d --build` поднимает Postgres, API, воркер загрузки и Caddy только на `127.0.0.1:8090`. В nginx добавляется блок из `deploy/nginx-tendergo.conf`, и он отправляет `/tendergo` в контейнер, а HTTPS остаётся за nginx. После настройки секретов `VPS_*` каждый пуш в `main` проходит CI и автоматически выкатывается на сервер.

Путь задаётся в одном месте, переменной `BASE_PATH` в `.env`: из неё собирается фронтенд, её используют Caddy, путь cookie входа и ссылки-приглашения.

## Ограничения источника данных

Готового открытого API у ЕИС нет, поэтому сервис разбирает публичные страницы поиска и извещений. Разбор вынесен в `backend/src/ingest/eis/parse.ts` и проверен тестами на настоящих страницах ЕИС. Если ЕИС поменяет вёрстку, править нужно только этот файл. Темп запросов задаёт `EIS_DELAY_MS`.

Из выдачи берутся только закупки на этапе «Подача заявок». Если закупку отменили, она исчезает из этой выдачи, и сервис об отмене не узнаёт: закупка остаётся в списке до окончания срока подачи заявок.

Официальная альтернатива — сервис выгрузки документов ЕИС (SOAP, нужен токен через Госуслуги). Его можно подключить как ещё один источник, реализовав интерфейс `TenderSource` из `backend/src/ingest/types.ts`.
